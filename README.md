# 섬데트 · SomedayTrip

> 언젠가 갈 여행을, 같이.

- **시작일**: 2026-10-19
- **사이트**: https://somedaytrip.vercel.app
- **상태**: 🔬 진행 중 (1단계 완료 · 서버 없음)
- **출발점**: [moon.log](../2026-10-15-moonlog-blog/)의 Plans(가고 싶은 곳) 기능을 떼어 내서, 여러 사람이 같이 짜는 서비스로 만든다. 블로그는 건드리지 않았다.
- **사용한 것**: Vite · TypeScript (프레임워크 없음) · [Leaflet](https://leafletjs.com) (BSD-2) · OSM 타일 · [Nominatim](https://nominatim.org) 장소 검색 · [qrcode](https://github.com/soldair/node-qrcode) (MIT)

## 무엇을 하는가

1. **누구나 계획을 만든다.** 가입은 없다. 계획을 만들 때 **주인 비밀번호**를 정한다.
2. **동네 여행도 된다.** 종류는 🏘️ 동네, 🚗 국내, ✈️ 해외 세 가지다. 날짜를 정하지 않고 "언젠가 · 1박 2일 · 벚꽃 필 때"처럼 둘 수도 있다.
3. **링크로 공유한다.** 링크를 아는 사람은 누구나 수정할 수 있다. 공유 창에서 링크 복사, 다른 앱으로 보내기, QR 코드를 쓸 수 있다.
4. **수정은 PR처럼 한다.**
   - 손님이 일정을 추가·수정·삭제하면 바로 바뀌지 않고 **제안 바구니**에 쌓인다. 화면에는 추가 예정(초록), 수정 예정(노랑), 삭제 예정(줄 긋기)으로 미리 보인다.
   - 다 고친 뒤 제목과 하고 싶은 말을 붙여 **제안**을 보낸다. GitHub의 PR과 같다.
   - 주인은 diff 카드(전 → 후)를 보고 **수락하거나 거절**한다. 한마디를 남길 수 있다.
   - 제안을 보낸 사람은 처리되기 전까지 **철회**할 수 있다.
   - 주인이 직접 고친 내용은 바로 반영된다. 모든 일은 **기록** 탭에 남는다.

## 주인은 어떻게 판단하나

**비밀번호를 아는 사람이 주인이다.** 쿠키나 기기에 기대지 않는다.

- **인증:** 비밀번호를 맞히면 주인 토큰을 준다. "이 브라우저에서 기억"을 켜면 localStorage에, 끄면 이 탭(sessionStorage)에만 남는다.
- **쿠키를 지워도 괜찮다.** 비밀번호만 다시 넣으면 된다. 다른 기기에서도 똑같다.
- **비밀번호 저장:** 원문은 저장하지 않는다. PBKDF2-SHA256(15만 회)으로 만든 해시와 솔트만 저장한다.
- **틀렸을 때:** 5번 틀리면 30초를 기다려야 하고, 그 뒤로는 틀릴 때마다 대기 시간이 두 배로 늘어난다.
- **비밀번호 변경:** 지금 비밀번호를 알아야 바꿀 수 있다. 바꾸면 다른 기기에 남아 있던 주인 인증은 모두 풀린다.
- **화면과의 경계:** 화면이 받는 데이터(`Bundle`)에는 해시도 토큰도 없다. 2단계에서 서버로 옮겨도 같은 경계를 그대로 쓸 수 있게 미리 나눠 두었다.
- **잊어버리면:** 비밀번호는 되찾을 수 없다. 만들 때와 공유할 때 두 번 경고한다.

## 동시 수정과 충돌

제안에 담기는 변경 하나는 **"원래 값 → 바꿀 값"**이다. 수락할 때 지금 계획과 비교한다(3-way).

| 상황 | 처리 |
|---|---|
| 그 사이 **다른 칸**이 바뀜 (주인은 메모, 손님은 시간) | 충돌이 아니다. 둘 다 반영된다 |
| 그 사이 **같은 칸**이 다른 값으로 바뀜 | ⚠️ 충돌. 카드에 "지금 계획에는 09:30으로 바뀌어 있어요"라고 보여 준다 |
| 고치려던 일정이 지워짐 | 충돌 (이미 지워진 일정) |
| 지우려던 일정이 이미 없음 | 통과 |
| 순서만 바뀜 | 충돌로 치지 않는다 |

충돌이 있는 제안은 그대로 수락할 수 없다. 주인이 할 수 있는 일은 두 가지다.
- **겹치지 않는 것만 수락:** 결과는 '일부 수락'이 되고, 빠진 변경은 흐리게 표시된다.
- **거절**

바구니 안에서 같은 일정을 여러 번 고치면 변경 하나로 합쳐진다. 원래 값으로 되돌리면 그 변경은 빠진다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 단위 테스트 (제안 병합·충돌, 저장소 권한)
npm run build
```

혼자서 친구 입장을 체험하는 방법은 두 가지다.
- 계획을 만들 때 "이 브라우저에서 주인으로 기억하기"를 끄고, 링크를 **새 탭**에서 연다. 새 탭은 손님이 된다.
- 주인 메뉴(⋯)에서 **손님 화면 미리보기**를 누른다.

탭끼리는 BroadcastChannel로 바로 동기화된다.

## 구조

```
src/
  types.ts              데이터 모양 (2단계 Supabase 테이블과 1:1)
  lib/store.ts          PlanStore 인터페이스 + LocalStore(localStorage) 구현
  lib/proposals.ts      제안 순수 로직: diff, 충돌 찾기, 반영, 바구니 합치기
  lib/crypto.ts         PBKDF2 비밀번호 해시
  lib/identity.ts       손님 닉네임 · 주인 토큰 · 제안 바구니
  lib/geo.ts            Nominatim 검색 (초당 1회 줄 세우기)
  pages/                home · new · plan · proposal
  ui/                   모달 · 지도 · 장소 고르기 · diff 카드 · 우표 그림
tests/                  vitest 22개
```

## 결과 (1단계)

- **단위 테스트 22개 통과.** 3-way 충돌, 바구니 합치기, 토큰 없이 수락 차단, 잠금, 비밀번호 변경 시 토큰 무효화, 일수 축소를 다룬다.
- **브라우저 시나리오 31개 통과, 콘솔 오류 0.** 주인 탭·손님 탭·인증 탭 세 개로 아래 순서를 돌렸다.
  1. 계획 생성
  2. 주인 직접 추가
  3. 손님 바구니와 제안
  4. 주인 화면에 실시간 반영
  5. 수락
  6. 충돌 표시
  7. 거절
  8. 틀린·맞는 비밀번호
  9. 손님 화면 미리보기
  10. 모바일(가로 넘침 없음)과 다크 모드
- **아쉬운 점과 한계**
  - 서버가 없어서 링크는 **같은 브라우저 안에서만** 열린다. 다른 기기에서 열면 "찾을 수 없어요" 안내가 나온다.
  - 비밀번호 검사가 브라우저에서 일어난다. 데이터 자체가 이 브라우저 안에 있으니 1단계에서는 의미가 있지만, 진짜 보안은 2단계 서버 검사부터다.
  - 충돌 판단이 변경 단위다. 한 일정의 시간과 메모를 같이 고쳤는데 시간만 겹쳐도 그 변경 전체가 빠진다.
  - Nominatim은 동네 가게를 잘 못 찾는다. 그래서 "지도에서 직접 찍기"를 넣었다.
